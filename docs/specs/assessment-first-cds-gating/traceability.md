# Assessment-First CDS Traceability Matrix

**Spec ID:** `a85cd2a1-fe98-4c21-b6f7-1b84c0327a2f`

**Authority:** ADR-20260703-01, ADR-20260723-01, and rapid-delivery amendment ADR-20260728-01.

**Delivery boundary:** The validated contract, documented technical baseline, implementation, and reproducible repository evidence authorize continuous work. Named Dev A, CEO, or Clinical Lead approval is not an implementation transition. Clinical review, pentesting, environment campaigns, canary observation, and production rollout are separate operational evidence and do not keep repository tasks open.

**Evidence posture:** Current executable evidence is recorded by `architecture/CDS_TASK_10_READINESS.md`, `backend/reports/cds-safety-regression.json`, `backend/reports/cds-resilience-campaign.json`, `backend/reports/cds-migration-rehearsal-local.json`, and feature-scoped security results. No absent environment or external evidence is inferred, but its absence is classified as deferred operational work rather than an implementation blocker.

## Legends

- **Design sections:** values are exact headings in `design.md`; `Section — Subsection` means exact parent and child heading. Key anchors are Architecture — OpenAPI-First Delivery Boundary; Assessment and Gate State Flow; Fail-Closed Assessment Change Protocol; Logical Staleness and Atomic Invalidation; Clinical Input Snapshot and Deterministic Routing; CPG Preview and Generation Eligibility; Lock Ownership and Liveness; Signed Gate Token Model; Protected Generation Sequence; Asynchronous Continuation Revalidation; Components and Interfaces; Data Models; Security, Privacy, and Clinical-Safety Controls; Observability and Operability; Migration, Deployment, and Rollback; Maintainability and Developer Experience; Continuous Delivery and Operational Evidence Boundary; Correctness Properties.
- **Operation groups:** **OP-ASMT** = `getCdsAssessment`, `updateCdsEditableAssessment`, `createCdsAssessmentConfirmation`, `updateCdsAssessmentConfirmation`, `deleteCdsAssessmentConfirmation`; **OP-CAND** = `createCdsDiagnosisCandidateEvaluation`, `getCdsDiagnosisCandidateEvaluation`, `getCdsDiagnosisCandidatePreview`, `createCdsDiagnosisCandidateSelection`; **OP-GATE** = `createCdsGateToken`, `createCdsRedFlagAcknowledgment`; **OP-VIEW** = `listCdsCurrentOutputs`, `listCdsOutputHistory`; **OP-GEN** = `createCdsPlanGeneration`, `createCdsPrescriptionGeneration`, `createCdsFinalIcdGeneration`, `createCdsMedicalCertificateGeneration`, `createCdsLabRequestGeneration`, `createCdsImagingRequestGeneration`, `createCdsPatientEducationGeneration`; **OP-LIFE** = `createCdsProtectedArtifactFinalization`, `createCdsProtectedArtifactRelease`; **OP-JOB** = `getCdsAsyncJob`, `createCdsAsyncJobCancellation`; **OP-LEGACY** = `rejectLegacyCdsSoap`, `rejectLegacyCdsPatientCard`, `rejectLegacyCdsDraftReview`, `rejectLegacyCdsAsyncContinuation` plus documented historical readers; **OP-ALL** = all preceding groups.
- **Schema/error groups:** **SCH-ASMT** = `CdsAssessmentState`, `CdsEditableAssessmentUpdateRequest`, `CdsAssessmentConfirmationRequest`, `CdsConfirmedAssessmentUpdateRequest`, `CdsAssessmentClearRequest`; **SCH-CAND** = `CdsCandidateEvaluationCreateRequest`, `CdsCandidateEvaluation`, `CdsDiagnosisCandidate`, `CdsDiagnosisCandidatePreview`, `CdsCandidateSelectionRequest`; **SCH-GATE** = `CdsGateTokenIssueRequest`, `CdsGateTokenIssueResult`, `CdsRedFlagAcknowledgmentRequest`, `CdsRedFlagAcknowledgmentResult`; **SCH-GEN** = `CdsProtectedGenerationRequest`, seven typed generation requests/payloads, `CdsProtectedArtifact`; **SCH-VIEW** = `CdsCurrentOutputs`, `CdsOutputHistory`; **SCH-JOB** = `CdsAsyncJobAccepted`, `CdsAsyncJob`, `CdsAsyncJobView`, `CdsAsyncJobCancellationRequest`; **SCH-LIFE** = `CdsProtectedArtifactFinalizationRequest`, `CdsProtectedArtifactReleaseRequest`; **SCH-LEGACY** = retired-route and historical-only shapes; **SCH-ALL** = all groups. **ERR-AUTH/STATE/TOKEN/GATE/ROUTE/IDEM/LEGACY** denote the fixed common and CDS machine-readable response families. **ERR-EVAL-FAILED** means `RED_FLAG_EVALUATION_FAILED`/service error plus durable `evaluation_failed` lock/revocation handling: `EVALUATION_FAILED` is never a successful `CdsRedFlagRouting` payload.
- **Data/manifests:** **DM-SESSION/INPUT/ASMT/TOKEN/ROUTE/CAND/ART/JOB/IDEM+OUTBOX/POLICY/MIG** are the exact target entity families catalogued in `DATA_MODEL.md` §1B. **TM-SESSION, ASSIGN, SOURCE, ASMT, CAND, EVAL, ACK, TOKEN, ASYNC, PUBLISH, LIFE, IDEM, POLICY** refer to the corresponding named transaction rows in `DATA_MODEL.md` §1D.1; **TM-APPLICABLE** means every state-changing manifest named by the criterion. No N/A row implies a hidden data dependency.
- **Controls/trust boundaries:** **TB-1..TB-10** are the exact trust-boundary register in `CDS_SECURITY_OPERATIONS.md` §3. **C-AUTH, CONCEAL, FENCE, LOCK, FAILCLOSED, KMS, TOKEN, GATE, CAND, DATA, IDEM, AUDIT, PHI, VALIDATE, LEGACY, MODE, OPS, CONTRACT, GOV, CLINQA** abbreviate the corresponding authentication, assignment concealment, revision fencing, reason-owned lock, fail-closed dependency, key, token, shared-gate, candidate-shape, persistence, idempotency, audit, telemetry/PHI, output-validation, retirement, server-mode, operations, contract, governance, and clinical environment-gate controls.
- **Evidence types / primary-ID suffixes:** **CT** contract validation; **UT** isolated unit example (not used where broader evidence is required); **PT** property/concurrency model; **IT** integration/transaction/fixture evidence; **HT** handler/end-to-end API evidence; **SEC** security/cryptographic/privacy evidence; **MIG** migration/classifier/reconciliation evidence; **OPS** infrastructure, load, alarm, runbook, restore, rollout, or rehearsal evidence; **GOV** governance/document/clinical-approval record. Fixture, migration, infrastructure, runbook, governance, and clinical-QA criteria are deliberately not pure UT rows.
- **Tasks:** W1 contract types/API foundations; W2 canonical Session/assignment/clinical input; W3 Assessment/candidates/red flags; W4 gate tokens/idempotency/protected generation; W5 async continuation/fenced publication; W6 finalization/separate release; W7 legacy retirement/migration; W8 frontend workflows; W9 Terraform/IAM/KMS/audit/alarms/operations; W10 bounded integrated repository validation. Pentesting, environment migration/load, staging, clinical review, canary, and production are deferred operational evidence, not W10 child tasks.
- **Status:** `baseline documented` means only that cited repository source documents establish the pre-delta baseline; it is not new implementation or execution evidence. `planned — not evidenced` means no qualifying evidence is claimed. `planned — delta contract validation pending` means the accepted requirement is not yet present in a revalidated OpenAPI contract. Contract validation, tests, migrations, deployments, rehearsals, clinical QA, canary, and production are never inferred from document acceptance.
