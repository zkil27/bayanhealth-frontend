# Kiro Agent Behavior Rules

## Shell Commands

Always use **bash-compatible** shell commands, not PowerShell or CMD syntax. This applies to all terminal commands generated by Kiro.

**Correct (bash)**:
- List files: `ls -la`
- Remove file: `rm file.txt`
- Remove directory: `rm -rf dir/`
- Copy file: `cp source.txt dest.txt`
- Create directory: `mkdir -p dir`
- Chain commands: `cmd1 && cmd2`
- Environment variables: `export KEY=value`
- Pipe: `cmd | grep pattern`

**Never use**:
- `Get-ChildItem`, `Remove-Item`, `Copy-Item`, `New-Item` (PowerShell)
- `del`, `rmdir /s /q`, `dir` (CMD)
- `;` as a command separator (use `&&` or `|`)

## Token Efficiency

- Skip restating the user's request back at them before answering.
- Skip filler phrases like "Great question!", "Certainly!", "Of course!".
- Prefer concise prose over bullet lists for simple answers.
- Do not summarize completed work at the end unless the user asks.
- Do not over-explain self-evident code.

## Progress and Authorization Boundaries

- Named-person approval is not a repository implementation gate. Continue bounded repository implementation, local validation, documentation, and non-destructive evidence generation without waiting for Dev A, CEO, Clinical Lead, or another named approver.
- Every environment or data mutation classified by the governing specification requires its own current, unused, operation-specific point-of-action authorization. Authorization for one operation, target, environment, or window cannot be reused or generalized.
- If the required authorization is missing, expired, already used, or mismatched to the exact operation, target, environment, or window, perform zero mutation and record `DEFER` with the mismatch.
- A governing specification may narrowly pre-authorize emergency disablement, credential or token revocation, or containment needed to stop active harm. Use only the smallest pre-authorized action, preserve evidence, record actor/time/scope/result, and reconcile state and Terraform/governance records immediately afterward; emergency authority never authorizes enablement, promotion, data migration, or broader remediation.
- Keep full-repository security remediation, penetration testing, environment load/fault campaigns, migration execution, clinical review, canary authorization/observation, external campaigns, and production rollout separate from feature implementation unless the user explicitly requests that operation.
- Scope validation findings to the feature. Record unrelated findings as follow-up work instead of silently expanding the active task across unrelated subsystems.
- A deferred external or operational activity does not keep a repository implementation task open.
